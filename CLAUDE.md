## Commands

### Run the application
```bash
cd project && python3 ui/main_window.py
```
**CWD must be `project/`** — `config.py` and `routing/discovery.py` resolve `../datas/config.ini` and `../datas/nodes.json` relative to the working directory, assuming it's `project/`. Running from elsewhere (e.g. `project/ui/`) silently reads/writes a different config under a stray `datas/` folder instead of the repo-root `datas/`.

### UI files — hand-maintained, do NOT regenerate
`project/ui/ui.py` is **hand-written**, not generated from `project/ui/fibre2uart.ui` (its `# Generated by pyside6-uic` header is misleading). `main_window.py` imports it directly (`from ui.ui import Ui_MainWindow`) and never reads the `.ui`; `fibre2uart.ui` is an out-of-sync orphan artifact.

**Never run `pyside6-uic` / `scripts/buildui.sh` to regenerate `ui.py`** — it overwrites the hand-written file with broken output and drops hand-written widgets (`btnReadVersion`, `tabThroughput`, `tabCmdTest`, the `_lblTerm*` labels). Edit `ui.py` by hand.

### Run tests
```bash
# Run all tests (generates timestamped .txt and .html reports in reports/)
python3 project/test_all.py

# Run a single module's test file
python3 project/test_config.py
python3 project/frame/test_frame.py
python3 project/protocol/test_protocol.py
python3 project/session/test_session.py
python3 project/routing/test_routing.py
python3 project/device/test_device.py
python3 project/events/test_events.py
python3 project/commands/test_commands.py
python3 project/transport/test_serial_transport.py

python3 tests/test_throughput.py
```

### Install dependencies
```bash
python3 -m pip install -r requirements.txt
# PySide6, pyserial, psutil
```

## Architecture

The project is a desktop app for communicating with cascaded fiber optic devices over a physical serial port, exposing each device's terminal ports as virtual serial ports on the host OS.

### Layered structure (top to bottom)

| Layer | Path | Role |
|-------|------|------|
| UI | `project/ui/` | PySide6 GUI, main window, panels |
| Public API | `project/api.py` | `FibreNetworkClient` — single entry point for all operations |
| Commands | `project/commands/` | Upgrade, system, port command handlers |
| Device | `project/device/` | `DeviceManager` + `Device`/`BoardInfo` models (discovered topology) |
| Events | `project/events/` | Async event bus (weak-ref subscribers) |
| Session | `project/session/` | Request/response pairing, sequence allocation, timeout |
| Routing | `project/routing/` | Logic address allocation, device discovery, hotplug |
| Protocol | `project/protocol/` | Frame codec, port paths, model/command enums |
| Frame | `project/frame/` | State-machine byte-stream parser, frame builder |
| Transport | `project/transport/` | Physical serial I/O threads (`SerialTransport`) |
| Virtual Serial | `project/virtual_serial/` | OS-level PTY (Linux) / com0com (Windows) virtual ports |

### Frame format
```
SOF(1) | check(1) | seq(1) | len(1) | cmd(1) | portLen(1) | port[0~N] | data[0~N]
```
- SOF `0xAA` = host→device, `0xAB` = device→host
- Command ranges: `<0x10` passthrough, `0x11–0x1F` upgrade, `0x21–0x2F` system, `0x31–0x3F` port config

### Device discovery & addressing
- Discovery uses recursive `0x24` (get_node_info) commands to walk the topology
- Logic addresses: relay nodes from `0x801`, terminal ports from `0x001`
- Routing table persisted to `datas/nodes.json` for faster startup
- Hotplug thread polls every 3 seconds for topology changes

### Virtual serial ports
- Linux: PTY pairs symlinked to `/dev/ttyVcom_0xXXXX`
- Windows: com0com virtual COM ports

### Configuration
- Config file auto-generated at `datas/config.ini` on first run
- Priority: CLI args > config.ini > built-in defaults
- Key CLI flags: `--hotplug`, `--rs485-timeout`, `--rs485-max-addr`, `-c <path>`

### Key design notes
- All UI updates posted to main thread via Qt signals
- `FibreNetworkClient` in `project/api.py` is the canonical API for non-UI code (tests, scripts)
- Transport layer auto-reconnects on USB disconnect
- Connection generation counter prevents stale frames after reconnect
- Test reports written to `reports/` as timestamped `.txt` + `.html` files (HTML has per-test detail)
