# 光纤通信转发模块

# 项目背景：
我需要做一个通信转发模块的上位机，电脑使用1个串口连接模块, 模块可以级联扩展，PC端操作每一个终端口都虚拟成一个串口

# 硬件
1. 光纤通信板，1个串口输入，6个光纤串口输出
2. 光纤桥接板：1个光纤串口输入，6个光纤串口输出
3. 光纤转485板：1个光纤串口输入，输出总共6个端口且可以根据硬件做配置：2个232或485, 2个CAN或485，2个485输出，485端口可连接485桥接板
4. 485桥接板：1个485输入，输出总共6个端口且可以根据硬件做配置：1个空闲，2个232或485, 2个CAN或485，1个485输出，

### USB通信
1. 波特率需要支持到1000000
1. 检测到USB通信断开后，UI提示错误信息
2. 连接成功后再使能断开检测，UI显示断开连接后则停止断开检测
4. 成功重连后自动重新发现并恢复虚拟串口
7. 将"发送"与"等待响应"分离：统一由一个发送线程串行发帧，响应通过 `Future`/`Event` 回调到各工作线程，串口层无竞争
8. 通信收发分别计数和错误计数，
9. 传输层关闭时批量清理future和event。

### 生成设备树流程：
1. 获取根节点信息(0x24)portLen=0
2. 对每一个PORT_FIBRE的端口获取下一个节点的信息，portLen=1
3. 对同一层级的多个 PORT_FIBRE 端口，使用多线程，将串行改为同层并行，提高通信效率，并行最多10个线程，其余线程排队，不使用协程
4. 对每一个PORT_485轮询查找地址1~0x7F，获取节点信息(0x24),如果没有节点回复（超时50ms），则为终端口
5. 485端口通信需要遵循1发1收或者广播发送的通信逻辑,
6. 每一个节点分配一个logicAddr，根节点logicAddr为0x801，
7. 每一个终端端口分配一个logicAddr, 从1开始分配, 
8. 并行发现阶段只收集节点信息，统一由主线程在汇总后按 DFS 顺序分配 logicAddr，完全避免并发写问题, logicAddr写入使用原子操作
9. 通过UI展示设备节点连接的拓扑结构，
10. 将设备树拓扑序列化到../datas/nodes_tmp.json文件,需要处理多线程写入问题, 搜索完成后再原子重命名为../datas/nodes.json, 
11. 启动时先加载nodes.json缓存，生成设备拓扑，检查玩version字段后，再启动设备热插拔检测功能，如有变化，则更新nodes.json
12. nodes.json顶层增加version字段，用来判断协议版本，加载时先检查版本号，版本不匹配则丢弃缓存并重新，同时记录日志提示
13. "version":"20260317",
14. 终端口无真实 UUID（硬件返回全零 bytes），必须在 PC 侧用 sha1(port_path)[:12] 生成合成 uid，保证每个终端口在 DeviceManager/TopologyView/TerminalPortList 中有唯一标识符
15. 支持热插拔检测

### portPath：
1. 有485端口的转发[port0, port1, rs485Addr, port3]
2. 无485的转发[port0, port1, port2]
3. rs485Addr只有可能出现在倒数第二个位置，所以可以增加字段"has485":true/false
4. PC端保存生成的设备树和logicAddr的关系，当发送目的地址为logicAddr时，解析成对应的portPath


### 虚拟串口
1. PC端对每一个终端口虚拟成串口进行收发操作,再解析成通信协议的格式由实际的标准串口发送到光纤通信板
2. 每一个终端口的虚拟串口在PC端生成设备，可以使用外部软件操作改虚拟串口
3. 每一个终端口生成的虚拟串口是可以被第三方串口打开的虚拟串口
4. 启动时扫描并清理 `/dev/ttyVcom_*` 残留 symlink（`os.path.islink()` + `os.unlink()`）
5. 注册 `atexit` 回调，正常退出时自动删除全部 symlink
6. 创建 PTY 后调用 `os.chmod(slave_path, 0o666)` 将 slave 端权限设为全局可读写，允许同机任意用户的第三方软件打开。
7. 虚拟串口设置为非阻塞模式
8. 需要对虚拟串口做吞吐量测试

### 升级
1. PC端可以单节点升级和广播升级，
2. 升级不需要断电续传功能
3. 出错后UI报错，然后自动再升级，3次后报错，等待用户操作再升级
4. 升级失败弹出UI提示返回的错误码
5. 升级进度条右边显示升级总时间，每次开始升级从0计时，格式为MM:SS
5. 升级面板目标下拉框由 DeviceFoundEvent/DeviceOfflineEvent 驱动自动维护（去重，仅包含非终端节点），不依赖设备树点击事件添加

### 通信测试
1. 在ui中选择待测终端口,
2. 终端口接物理串口工具再连接到PC, ui中选择该串口号
3. 发送数据,小包数据(数据段1个字节),大包数据(数据段240个字节)
4. 每一包数据seq+1,按顺序发送,未接收到需要重传
5. PC端从USB口发送数据，终端口的串口工具收到后, 记录RTT等参数, 再原样返回数据，记录返程RTT

#### 需要验证的性能
1. 协议效率：实际数据量 / 线路传输总量， 区分大小包
2. 丢帧率：发送帧数 vs 成功接收帧数
3. 顺序错误率：SN 乱序的比例
4. 超时重传次数/总传输次数
5. 突发模式,短时间大量请求
6. 持续模式,长时间稳定速率
7. 混合模式:大小包+突发+持续
8. 监控CPU使用率, 内存使用:队列,缓冲区,Future对象数量
9. 显示待发送队列数量,
10. 线程状态:发送接收是否卡死/繁忙
11. GC 压力（Python）：对象创建/销毁频率
12. 多级通信转发影响:不同 port_path 深度对延迟的影响
13. 广播 vs 单播的性能差异
